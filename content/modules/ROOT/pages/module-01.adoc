ようこそ！このラボでは、Ansible Automation Platform の **Automation Controller** のWebベースユーザーインターフェース（Web UI）を学びます。

ハンズオン演習を通して、Web UI を使って Ansible Playbook を管理・実行する手順を確認します。最初に画面を確認し、サーバー管理用の **Inventory** を作成し、Playbook を **Project** に取り込み、それらを実行する **Job Template** を追加し、最後にそれらを連携する **Workflow** を作成します。


---

== ラボのヒント

開始前に、ラボ体験をより良くするための基本的なヒントを確認してください。

. **Instructions サイドバー**（この文章を読んでいる場所）は、境界線をドラッグしてサイズ変更できます。メインパネルを広く使いたいときに便利です。

. **Next** をクリックする前に、各チャレンジの手順を完了させてください。一部のチャレンジでは、作業内容が検証されます。もし何か不足している点があれば　"validation failed" というメッセージが表示され、修正すべき内容の詳細が示されます。

. チャレンジを完了したら、説明文の下部にある青色の **Next** ボタンをクリックして次に進んでください。

. 行き詰まった場合は、**Solve** をクリックすると、現在のチャレンジが自動的に完了します。これにより、次のチャレンジに進むための必要なすべてのオブジェクトがセットアップされます。

. Automation Controller へのログイン情報は次のチャレンジで確認できます。

. 演習を始めるには、下の青色の **Next** ボタンをクリックしてください。

== 演習の概要

これから行う演習の概要は以下のとおりです。各チャレンジは前のチャレンジに基づいて構成されているため、ラボの最後には完全に動作する自動化環境を構築できます。

. **Dashboard の理解** — Automation Controller の Web UI、主要セクション、ナビゲーションについて理解を深めます。
. **Inventory の作成** — Playbook の対象となる Host と Group を定義します。
. **Project のインポート** — Ansible Playbook を含む Git リポジトリを Controller に接続します。
. **Credential の理解** — Controller が管理対象ホストの認証情報を安全に保存および管理する方法を確認します。
. **Job Template の作成** — Inventory、Project、Credential を組み合わせて、Web UI から Playbook を実行します。
. **2つ目の Project のインポート** — 今後のチャレンジで使用する追加の Playbook を含む別の Git リポジトリを追加します。
. **Job Template の追加作成** — これまでに学んだことを活かし、異なる Playbook を使用し、異なる Host を対象とする Template を作成します。
. **Workflow Job Template の作成** — 条件ロジックと並列実行を用いて、複数の Job Template を連結します。
. **Survey の追加** — Job 実行時にユーザー入力を促し、各 Job の実行をカスタマイズします。

== Controller as Code (CaC) の紹介

Throughout this workshop, you will create automation controller objects (inventories projects, credentials, job templates, and workflows) using the web UI. However, in production environments, these same objects can be managed **declaratively as code** using the link:https://github.com/redhat-cop/infra.aap_configuration[infra.aap_configuration^] collection.

このワークショップでは、Web UI を使用して Automation Controller オブジェクト (Inventory、 Project、 Credential、 Job Templates、 Workflow) を作成します。ただし、本番環境では、これらのオブジェクトを次のリンク先にあるコレクション (link:https://github.com/redhat-cop/infra.aap_configuration[infra.aap_configuration^]) を使用して、**宣言的にコードとして** 管理できます。

このアプローチは **Controller as Code (CaC)** と呼ばれ、以下のことが可能になります。

* すべての Controller オブジェクトを YAML 変数として定義する
* 単一の Playbook でそれらを冪等的に適用する
* Controller 構成全体をバージョン管理する
* 開発環境、ステージング環境、本番環境間で環境を一貫して再現する

各チャレンジの最後には、UI で作成したオブジェクトを宣言的な YAML で表現する方法を示す**Controller as Code Alternative** セクションがあります。これらのセクションでは、このリポジトリの `controller-as-code/` ディレクトリを参照しています。
